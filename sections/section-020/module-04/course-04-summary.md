# Summary

Release diagnosis compares the intended artifact and configuration with observed workload progress. Different failures require evidence from different lifecycle stages.

A useful correction addresses the demonstrated cause and is checked through meaningful application behavior. Returning to an earlier template does not universally restore external configuration or data, so compatibility and retained evidence remain necessary.

Diagnosis becomes stronger when each hypothesis predicts evidence at a specific boundary. Verification repeats the original observation after correcting the responsible setting and confirms that the intended version, readiness and request behavior agree.
